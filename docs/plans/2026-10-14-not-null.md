## 1. Background

2026.10.2 made NULL first-class (per-record null bitmap; see
2026-10-10-null-bitmap.md). NULL is the answer for "omitted, no default"
and a legal target of explicit `null` writes on every field. Operators
need the SQL `NOT NULL` ability to exclude that answer per field.

The bitmap machinery already stores the truth per record; `:not_null` is a
schema-level invariant over it. Nothing about record bytes, btree keys
(NULL tier), cursors, or the engine-version slot changes.

**Invariant this feature maintains:** on any object, for every field with
`not_null=1`, zero live records have that field NULL — where NULL is the
generation-aware predicate of §3.4. Every task below either establishes
the invariant on new writes or proves it before enabling it on existing
data.

## 2. Decisions

- **D1 — every write branch that would produce NULL is rejected on a
  `:not_null` field.** Enumerated exhaustively in §3.2 (five encoder
  branches + one branch on each of three update paths). Explicit JSON
  `null` → request error even when the field has a `:default=` (SQL rule:
  DEFAULT applies to omission, never to explicit NULL). Omitted field,
  no default → request error. Declaring `:not_null` without a default is
  legal; it makes omission an error. Malformed uuid/ipv4/ipv6 values are
  also rejected: under the 2026.10.2 sentinel convention they *store
  NULL*, which the constraint forbids (a well-formed `0.0.0.0` / `::` /
  nil-uuid parses and stays a real bit-clear zero — allowed).
- **D2 — error granularity follows the write path.** Single insert/update
  and criteria-form bulk update: whole-request `{"error":"field '<name>'
  is not nullable"}` (canonical text via `fmt_not_null_err`, §3.1).
  Per-record JSON bulk insert/update: per-record skip under the existing
  convention (null plan locked decision 5: `errors++`/`skipped++` +
  `continue`) — the wire counters stay counts-only (no per-record message
  channel exists on those paths); the field name goes to the log via
  `LOG_WARN`. Bulk-insert JSON gets this for free: the encoder returns
  `-2` and the existing handler at query_bulk.c:1604 counts the error.
- **D3 — schema mutations.**
  - `create-object` and `add-field` accept `:not_null` freely (add-field
    backfills/rebuilds existing records — new fields are never NULL, null
    plan §2.10).
  - **Modifier resolution on edit-field** mirrors the `:default=` carry
    convention (rewrite_fields_conf_for_edit): the edit line's explicit
    token wins; **omission carries the old `:not_null` forward** —
    `edit-field age:long` never silently drops the constraint. **Removal
    is the explicit trailing token `:nullable`**, which edit-field strips when rewriting
    (a fresh create-object/add-field may persist the legal no-op token
    verbatim; it loads as unconstrained). Removing `:not_null` is always
    legal, no scan. Default modifiers and nullability resolve
    **independently**; the rewritten line is emitted canonically — exactly
    one default modifier, then at most one nullability token (§3.3).
  - **Adding `:not_null` via edit-field** requires a read-only,
    generation-aware, fail-closed NULL scan of the object's live records
    (§3.4) finding zero NULLs in that field. The gate runs under the
    `objlock_wrlock` the schema-mode dispatch already holds
    (server.c:1542 `mode_is_schema`), before the `dry_run` early returns
    and before any metadata write or rebuild — a dry run must predict the
    refusal. Nonzero NULLs → refuse with the count; invalid live
    reference, unreadable record, or unopenable object → refuse (fail
    closed). No data rewrite in any case.
- **D4 — no format/migration impact.** No schema.conf engine-version bump,
  no fields.conf layout change beyond two more optional trailing tokens,
  no reindex or data migration. A read-only startup ambiguity audit
  precedes upgrade (Task 1). Release metadata is NOT touched: the
  feature ships inside the unreleased 2026.10.2 (rev 6 — no version
  bump). Older binaries can't open a root
  stamped by this release anyway (existing version gate refuses both
  directions), so unknown-token forward-compat is moot.
- **D5 — `:not_null` is strictly per-field.** Composite indexes
  (`field1+field2`) are index-spec names referencing multiple TypedFields;
  there is no composite-level modifier. Each component field carries its
  own flag, and composite index NULL semantics are unchanged (any NULL
  component → NULL composite key, per the existing BTRI tier rule). An
  operator wanting "both parts mandatory" declares `:not_null` on each
  component field. `:auto_create`/`:auto_update` always stamp values, so
  they trivially satisfy `:not_null` (redundant combination allowed; the
  auto_create *preserve* branch could only carry a NULL forward if the
  field already had one, which D3's gate prevents — and pre-gate records
  can't gain the flag).
- **D6 — no new query shortcuts.** `not_exists` on a `:not_null` field
  could constant-fold to 0 rows; do NOT add that shortcut. The 2026.10.2
  review removed exactly this class of bypass because it can't track
  future semantic changes. Document as possible future work behind a
  generation-aware guard.

Error text (add to docs/reference/error-codes.md, Task 6):
`field '<name>' is not nullable` — the canonical single-request text, and
the text logged (with path context) on bulk per-record skips.

## 3. Grammar and enforcement design

### 3.1 fields.conf grammar, parsing, structural validation

```
name:type[:size|P,S][:default=...][:auto_create|:auto_update][:not_null|:nullable][:removed]
```

`[:not_null|:nullable]` is a **trailing** token pair (at most one), after
any default modifier. `parse_default_modifier` strips trailing
`:not_null`/`:nullable` **first**, because its `:default=` scan consumes
to end-of-string. `:removed` is stripped by `load_typed_schema` before
`parse_default_modifier` runs, so `int:not_null:removed` also parses.

**Structural validation (rev 3).** A trailing-token strip alone is not
enough: exact-match types (`int`, `uuid`, …) fail closed on leftover
tokens, but `varchar:N` and `numeric:P,S` parse via `atoi`/`strchr` and
tolerate trailing bytes, and an enum value list can absorb a token. So
after the trailing strip, every parse site rejects any *further*
occurrence of either token:

- `parse_default_modifier` (config.c) returns **-1** on invalid structure.
  Shared by `load_typed_schema` (config.c:1707) and `parse_field_line`
  (query_find.c:676 — the edit-field validator at query_schema.c:472 and
  the add-field staging at query_find.c:1393), so one change covers load,
  add, and edit staging. cmd_add_fields also calls it directly during
  pre-validation and must handle -1 before any rebuild. Load refuses the entire schema on -1: skipping a column would shift
  subsequent offsets and NULL bitmap positions. The wire gates turn it
  into "Invalid field line".
- `validate_field_type_clean` (query_schema.c) — create-object's
  validator — applies the same strip-then-reject rule (its own copy; it
  does not call `parse_default_modifier`).
- The create-object **enum-default membership check**
  (query_schema.c:1011-1042) takes the literal to end-of-spec; it must
  exclude a trailing nullability token from `dlen`, otherwise
  `status:enum(open,paid):default=open:not_null` is rejected with "not in
  the declared value list" even though the grammar is correct.
- `field_default_too_long` is left unchanged: its length includes the
  token, which is conservative by 9 bytes against the 255-byte
  `default_val` capacity — safe direction, documented here.

**Deliberate restriction:** an enum value *name* containing the substring
`:not_null` or `:nullable` (e.g. `enum(a,b:not_null)`) is rejected by the new wire grammar; malformed new-generation schema
refuses load — the structural rule cannot distinguish it
from a modifier, and a value named like a modifier is pathological.
Old roots are NOT interpreted with this new rule until the raw audit
below passes. Documented in typed-records.md (Task 6).

**Compatibility policy:** trailing tokens are ambiguous with old enum names
and literal defaults. Task 1 adds `shard_db_not_null_upgrade_audit`, shared
by daemon and embedded startup through `shard_db_recover_before_stamp`.
For evidence older than 2026.10.2 — the current, unreleased version;
i.e. any 2026.09.2-or-older stamp — (or missing evidence), it reads raw
fields.conf files and refuses roots containing either reserved substring
on a non-comment field line, before recovery uses the new parser and before
any version stamp. It never edits fields or records. Resolve ambiguity
using the previous release's supported schema edits (change a default or
rename an enum value with explicit allow_rename, preserving stored value
positions); do not delete columns or manually stamp the root. A clean older
root opens and is stamped normally. Absent stale object directories are
skipped, matching existing startup validation; unreadable/missing metadata
on a materialized object still refuses upgrade. Roots already stamped 2026.10.2 use the
new grammar. This is an explicit upgrade restriction, not silent schema
reinterpretation; tests cover both daemon and embedded shared preflight.

**Not in scope:** tightening `parse_field_type` to require full-spec
consumption generally (varchar/numeric trailing-garbage tolerance is
pre-existing wire+load behavior; tightening it would drop
previously-accepted on-disk specs — a schema-shift risk unrelated to this
feature).

`TypedField` gains `uint8_t not_null; uint8_t not_null_set;` —
`not_null_set` distinguishes "edit line stated nullability explicitly"
from "omitted" for the D3 carry rule. Both are zeroed by every existing
construction-site memset, defaulting to unconstrained.

Canonical error formatter (single source, used by every rejection site):

```c
/* config.c, after fmt_unknown_enum_err */
/* Canonical :not_null rejection text — one source so the single-request
   error, the bulk LOG_WARN lines, and docs/reference/error-codes.md stay
   identical. err_buf may be NULL/0 (the no-channel encoder passes none). */
void fmt_not_null_err(const TypedField *f, char *err_buf, size_t err_buf_size) {
    if (!err_buf || err_buf_size == 0) return;
    snprintf(err_buf, err_buf_size, "field '%s' is not nullable", f->name);
}
```

Declared in types.h beside the encoder declarations (Task 1).

- The other fields.conf writers need nothing: create-object writes the
  client's spec strings verbatim (query_schema.c:1296), the rebuild

- `cmd_describe_object` (query_schema.c:1630) renders `"not_null":true`
  per constrained field.

### 3.4 edit-field add-gate (strict, generation-aware, fail-closed)

New `slotcask_walk_live_strict` in slotcask.c validates and visits every
flag=1 keyfile entry in ONE pass while retaining its segment handle. Every
keyfile/segment acquisition error, invalid stream, truncated record, or
hash/flag mismatch returns failure; no entry is silently skipped. The
callback receives a bounded record only after reference validation. The
caller holds objlock_wrlock, so mismatch cannot be explained by concurrent
writes. No refs-array allocation or second traversal exists.

The query_schema.c callback classifies nullmap records by the field bit
and legacy records via `legacy_field_absent` on a zero-padded bounded copy.
A `typed_record_view` failure aborts the strict walk and refuses the edit.

**Concurrency (corrected):** `slotcask_walk_live_strict` is **sequential**
in this plan. Plain counters suffice; the callback
uses the existing SlotcaskScanCb signature. A future parallel implementation
must revisit the plain counters and shared scratch buffer. The caller (`cmd_edit_fields`) is under `objlock_wrlock` for
the whole dispatch (schema-mode), so no concurrent writer can slip a NULL
in between scan and fields.conf swap, and the registry handle cannot be
invalidated mid-walk.

Gate placement in `cmd_edit_fields`: after `new_ts` construction and the
`needs_rebuild` computation, **before** the `if (!needs_rebuild) { if
(dry_run) ...` early return (query_schema.c:653) and therefore also
before the metadata-only `rewrite_fields_conf_for_edit` call (660) and
the rebuild path (whose own dry-run return at 700 is likewise downstream).
One insertion point covers all three.

/* Strip default/nullability modifiers in place. Returns 1 when a default
   modifier was stripped, 0 when none was present, -1 when the modifier
   STRUCTURE is invalid: a :not_null / :nullable token appears anywhere
   except as the single trailing token (duplicates included). Callers
   must treat -1 as an unparsable spec — reject at the wire, refuse the whole schema at load. */
int parse_default_modifier(char *type_spec_inout, TypedField *tf) {
    if (!type_spec_inout || !tf) return 0;
    /* Trailing nullability tokens (:not_null / :nullable) strip FIRST —
       the :default= scan below consumes to end-of-string, so a token
       after it would be swallowed into the default literal. Grammar:
       [:not_null|:nullable] is the LAST modifier (:removed is stripped
       by load_typed_schema before this runs). */
    tf->not_null = 0;
    tf->not_null_set = 0;
    size_t spec_len = strlen(type_spec_inout);
    if (spec_len >= 9 &&
        strcmp(type_spec_inout + spec_len - 9, ":not_null") == 0) {
        type_spec_inout[spec_len - 9] = '\0';
        tf->not_null = 1;
        tf->not_null_set = 1;
    } else if (spec_len >= 9 &&
               strcmp(type_spec_inout + spec_len - 9, ":nullable") == 0) {
        type_spec_inout[spec_len - 9] = '\0';
        tf->not_null_set = 1;   /* explicitly unconstrained */
    }
    /* Structural rule: at most ONE nullability token, trailing. After
       the strip above, ANY remaining occurrence is invalid. Exact-match
       types would fail in parse_field_type anyway, but varchar/numeric
       parse via atoi and tolerate trailing bytes, and an enum value list
       can absorb a token — enforce explicitly. */
    if (strstr(type_spec_inout, ":not_null") ||
        strstr(type_spec_inout, ":nullable"))
        return -1;
    char *dflt;

/* Rewrite the live record `key` in place with hdr2_byte and new_vlen
   value bytes. Fixed-size slots keep the shrink in-slot. Returns 1 on
   success. Run with the daemon STOPPED. */
static int nn_surgery(const char *obj_dir, const char *key,
                      uint8_t hdr2_byte,
                      const uint8_t *new_value, size_t new_vlen) {
    char streams[768];
    snprintf(streams, sizeof(streams), "%s/data/streams", obj_dir);
    DIR *sd = opendir(streams);
    if (!sd) return 0;
    size_t klen = strlen(key);
    int done = 0;
    struct dirent *de;
    while (!done && (de = readdir(sd)) != NULL) {
        if (de->d_name[0] == '.') continue;
        char sub[832];
        snprintf(sub, sizeof(sub), "%s/%s", streams, de->d_name);
        DIR *sdir = opendir(sub);
        if (!sdir) continue;
        struct dirent *fe;
        while (!done && (fe = readdir(sdir)) != NULL) {
            if (!strstr(fe->d_name, ".dat")) continue;
            char fp[1088];
            snprintf(fp, sizeof(fp), "%s/%s", sub, fe->d_name);
            FILE *f = fopen(fp, "r+b");
            if (!f) continue;
            fseek(f, 0, SEEK_END);
            long sz = ftell(f);
            for (long off = 0; off + 24 <= sz && !done; off += 8) {
                uint8_t hdr[24];
                if (fseek(f, off, SEEK_SET) != 0) break;
                if (fread(hdr, 1, 24, f) != 24) break;
                if (hdr[18] != 1) continue;
                uint16_t kl = (uint16_t)(hdr[16] | (hdr[17] << 8));
                if (kl != klen) continue;
                char kb[64];
                if (fread(kb, 1, (size_t)kl, f) != (size_t)kl) break;
                if (memcmp(kb, key, (size_t)kl) != 0) continue;
                uint32_t old_vlen = (uint32_t)hdr[20] |
                                    ((uint32_t)hdr[21] << 8) |
                                    ((uint32_t)hdr[22] << 16) |
                                    ((uint32_t)hdr[23] << 24);
                if (fseek(f, off + 19, SEEK_SET) != 0) break;
                fputc((int)hdr2_byte, f);
                fputc((int)(new_vlen & 0xFF), f);
                fputc((int)((new_vlen >> 8) & 0xFF), f);
                fputc((int)((new_vlen >> 16) & 0xFF), f);
                fputc((int)((new_vlen >> 24) & 0xFF), f);
                if (fseek(f, off + 24 + (long)kl, SEEK_SET) != 0) break;
                fwrite(new_value, 1, new_vlen, f);
                for (uint32_t z = new_vlen; z < old_vlen; z++) fputc(0, f);
                done = (fflush(f) == 0);
            }
            fclose(f);
        }
        closedir(sdir);
    }
    closedir(sd);
    return done;
}

                    padded > sh.map_size - entry->offset ||

   Read-only generation-aware NULL count for one field, used by
   cmd_edit_fields before any :not_null-adding edit is applied (D3).

   Uses slotcask_walk_live_strict: each live keyfile entry is validated
   and visited while the segment handle is held; acquisition failures
   return failure. Callback decode failures also refuse the edit.
   The walk is sequential; caller holds objlock_wrlock throughout. */
typedef struct {
    const TypedField *fld;      /* field under test                      */
    int               field_idx;
    uint8_t          *scratch;  /* fld->size bytes — legacy bounded copy */
    int64_t           nulls;
    int               broken;
} NotNullScanCtx;

static int not_null_scan_cb(const uint8_t hash16[16], const void *key,
                            size_t klen, const void *value, size_t vlen,
                            uint8_t hdr2, void *ud) {
    (void)hash16; (void)key; (void)klen;
    NotNullScanCtx *c = (NotNullScanCtx *)ud;
    const uint8_t *base = NULL; const uint8_t *bm = NULL;
    int bm_bytes = 0; size_t region = 0;
    if (typed_record_view((const uint8_t *)value, vlen, hdr2,
                          &base, &bm, &bm_bytes, &region) != 0) {
        c->broken = 1;
        return 1;   /* stop the walk — caller fails closed */
    }
    int is_null;
    if (hdr2 & SREC_FLAG_NULLMAP) {
        is_null = typed_field_null(bm, bm_bytes, c->field_idx);
    } else {
        /* Legacy: bounded zero-padded copy, exactly how
           update_compose_new_from_old materializes dst — short or
           trim-compacted records scan as absent (NULL), matching what
           the next rewrite would render. */
        size_t avail = (region > (size_t)c->fld->offset)
            ? region - (size_t)c->fld->offset : 0;
        size_t copyn = avail < (size_t)c->fld->size ? avail
                                                    : (size_t)c->fld->size;
        memset(c->scratch, 0, (size_t)c->fld->size);
        if (copyn) memcpy(c->scratch, base + c->fld->offset, copyn);
        is_null = legacy_field_absent(c->fld, c->scratch);
    }
    if (is_null) c->nulls++;
    return 0;
}

   cannot be opened, any live reference is invalid, the walk fails, or
   any live record failed validation (fail closed). */

                                 const TypedSchema *ts, int field_idx,
                                 int64_t *out_nulls) {
    *out_nulls = 0;
    if (!ts || field_idx < 0 || field_idx >= ts->nfields) return -1;
    const TypedField *fld = &ts->fields[field_idx];
    Schema sch = load_schema(db_root, object);
    if (sch.splits <= 0 || sch.slot_size <= 0 || sch.streams <= 0) return -1;
    SlotcaskSchemaInfo info = {
        .splits = sch.splits, .slot_size = sch.slot_size,
        .streams = sch.streams,
    };
    SlotcaskDb *sdb SDB_REG_REF = slotcask_registry_get(db_root, object, &info);
    if (!sdb) return -1;
    uint8_t *scratch = malloc((size_t)(fld->size > 0 ? fld->size : 1));
    if (!scratch) return -1;
    NotNullScanCtx ctx;
    memset(&ctx, 0, sizeof(ctx));
    ctx.fld = fld;
    ctx.field_idx = field_idx;
    ctx.scratch = scratch;
    int wrc = slotcask_walk_live_strict(sdb, not_null_scan_cb, &ctx);
    free(scratch);
    if (wrc != 0) return -1;   /* walk-level failure (defense in depth) */
    if (ctx.broken) return -1;
    *out_nulls = ctx.nulls;
    return 0;
}

## 6. Invariants and edge cases (explicit)

- A bit-clear zero is a VALUE, not NULL: `0.0.0.0`, `::`, nil-uuid,
  midnight, `0`, `0.0`, `""` on a `:not_null` field are all legal.
- Malformed uuid/ipv4/ipv6 on a NON-constrained field: unchanged
  behavior (stores NULL via the sentinel convention) — enforcement is
  strictly modifier-gated (Task 3 step 5 control proves it).
- Malformed uuid/ipv4/ipv6 on an UPDATE of a constrained field: stores a
  bit-clear zero via `encode_field` (no NULL produced) — pre-existing
  behavior for all fields, unchanged here, documented as a known edge in
  typed-records.md.
- `:not_null` + `:default=`/`seq()`/`uuid()`/`random(N)`/`auto_create`/
  `auto_update`: all legal; defaults satisfy the constraint because the
  defaults pass materializes values; explicit null still errors (D1).
- Tombstoned fields: `name:type:not_null:removed` parses (the `:removed`
  strip runs first); a tombstoned field's flag is inert (its bit is
  never tested after removal — bit positions shift per null plan §2.10).
- Modifier structure: at most one nullability token, trailing; tokens
  buried mid-spec are rejected on EVERY type (Task 1 step 5), not just
  exact-match types; enum value names may not contain the token
  substrings (documented restriction, §3.1).
- The edit-gate scan and the enforcement flag are consistent under
  mixed-generation data: the gate counts legacy-absent rows as NULL, and
  the rewrite composers would convert exactly those rows to NULL bits on
  their next rewrite — the gate refuses precisely the set that would
  violate the invariant after conversion. No legacy-format support is
  added; mixed generations within v2 are 2026.10.2 behavior.
- Gate completeness: slotcask_walk_live_strict validates and visits every
  live entry in one pass and fails on any acquisition or reference error;
  the permissive walker is not used by this gate.
- Crash safety: every rejection happens at parse/encode, before staging
  or KFM2 markers; the gate is read-only before an atomic
  fields.conf.new + rename; the rebuild path has its existing
  transaction. No new recovery path needed.
- Concurrency: the gate runs under the `objlock_wrlock` that schema-mode
  dispatch already holds (server.c:1542); `walk_live_strict` is sequential
  today and the callback keeps to the `SlotcaskScanCb` contract; no new
  lock ordering.
