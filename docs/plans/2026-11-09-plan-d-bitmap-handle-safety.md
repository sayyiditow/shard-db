# Plan D — bitmap handle safety and complete read results

## Brief

**Primary goal:** Queries either return complete, correct results or a clear error when a required bitmap cannot be read; cache pressure must never produce an unlocked bitmap handle.

**Problem/root cause:** With the cache initialized, saturated readers and stale-inode opens can still return independent mappings without an entry lock. A keyfile rebuild can change their layout in place. Rebuilds also skip damaged bitmaps without retiring cached mappings, while several readers turn failed opens into missing candidates or groups.

**Logical flow**
1. Open a locked cache handle, or retry admission briefly and fail. Preserve C's actual lock errors and ordinary blocking contention.
2. Before accepting a corrupt-bitmap skip, release its current handle and retire its cache entry with checked error handling; retain startup-repair evidence.
3. Distinguish an unwritten/missing shard from an actual read failure. Discard incomplete collections; retain only whole-result record-scan fallbacks.
4. Finish bitmap candidate preparation and required totals before a find response starts. Then filter records, paginate and emit through existing executors.

| Decision | Alternatives | Why | Tag |
|---|---|---|---|
| Keep cached-only production opens; initial attempt plus four admission retries, 2 ms apart | Unlocked mappings; unlimited admission retries | Excludes in-place remaps and bounds fallback churn; existing blocking lock waits remain | DEFAULT (prior F3 choice retained) |
| Abandon the rebuild if checked retirement fails | Ignore failure; add persistent quarantine | Ignoring it breaks the safety claim; quarantine adds state and recovery machinery | NEEDS YOU |
| Prepare bitmap candidates before emission, including small-limit finds | New response spool; keep streaming through bitmap opens | Reuses bounded collections and prevents bitmap failures after response bytes; may increase small-limit latency/memory | NEEDS YOU |
| Missing AND input may establish an empty shard; safe record fallbacks remain | Open every logically unnecessary file and error on any damage | Keeps existing missing-file semantics without silently losing required matches | DEFAULT |
| Prefer 8,192 actual bitmap-candidate slots, within the remaining budget; scan on insertion overflow | Live resizing; another build attempt; transient errors | More headroom for small sets without new table synchronization; fallback preserves complete results | NEEDS YOU — approved 2026-11-10 |

**Blast radius:** `bitmap.c/.h` cache admission, corruption errno and invalidation contracts; `slotcask.c` remap preparation; `query.c`, `query_internal.h`, `query_aggregate.c` internal emit/popcount/candidate consumers; `query_plan.c` estimates; `keyset.c`/`types.h` exact allocation sizing and request-owned candidate budgets. Consumers are enumerated below. No disk format, config or response-shape changes; pressure/damage can now produce errors instead of unlocked handles or partial success. Schema index-building retains its existing best-effort policy.

**Tests:** Saturation and recovery; stale publication with a held old reader; C error/ordinary-contention preservation; both corrupt-skip branches and retirement failure; count/find/aggregate exactness and valid standalone error responses; missing shards and safe fallbacks; startup repair. Each bug family gets base-red/fixed-green/revert-red/restored-green proof, with bounded watchdogs.

**Out of scope:** Ownership/deadlock detection, redesigning pools, immediate repair scheduling, startup repair scope (E), adaptive fetching (H), benchmarks and the final branch sanitizer gate.

### Phase 2 — cached-only admission and reliable corruption errno

**How this serves the primary goal:** Every production bitmap handle remains protected from in-place layout changes.

Test-first: Phase 1 saturation/stale cases, including C's error matrix, precede edits to `bitmap.c`.

In `bm_open_impl`, keep no-cache fixtures unchanged and remove the two initialized-cache uncached returns. Add one shared admission retry counter **before** `retry_bm_acquire`; initial attempt plus four retries, with a 2 ms sleep only between retries. Release table/entry locks and dispose prospective private map/fd before sleeping. Count saturated no-slot retries (including writer identity-change retry) and stale retirement retries against this shared budget. Keep the existing per-attempt hit identity checks and fill-reuse checks; do not describe the whole operation as time-bounded: actual lock acquisitions still block normally.

Stale mismatch: record unlock instrumentation, unlock the acquired entry exactly once, then call `bm_cache_invalidate_nowait`. A negative result returns immediately with saved exact errno. Zero or successful retirement consumes a retry and restarts cached acquisition; exhaustion yields EBUSY. Do not directly map/return the new inode. Keep generation sampling before pathname open and generation validation on hits; `bm_after_rename` remains nonblocking with its existing void/error-discard publication policy.

Cache saturation: extend C's first-error precedence to readers as well as writers. A later successful eviction may satisfy the open despite an earlier try error; a selected blocking wait error overrides earlier try errors; if no success exists, return the first applicable hard error, never replace it with EBUSY. If no error exists, dispose private resources and retry admission, finally EBUSY. Keep selected blocking writer eviction and its C matrix unchanged. Installed maps remain cache-owned on failed fill; retries must not close/unmap them.

In `bm_file_open_mmap`, preserve actual syscall errno across close/unmap. A short file or invalid magic is deterministic EUCLEAN, as are the already-detected invalid stride/body bounds; never return -1 with stale ENOENT or zero errno. Do not expand this into a complete hostile-file parser redesign. Normalize only existing rejection branches and their exact arithmetic checks. Cover short header, invalid magic, invalid layout and syscall failures independently.

Update `bitmap.h`/publication comments to state cached-only initialized behavior and distinguish admission bounds from total lock-wait duration. Keep `bm_handle_cached` as remap defense in depth.

### Phase 3 — checked retirement before a corrupt skip

**How this serves the primary goal:** A rebuild cannot accept skipping a damaged file while continuing to serve its cached mapping.

Test-first: both retirement branches and injected retirement failure must be demonstrated before modifying `slotcask.c::kf_bmfix_prepare`.

- Failed-open branch: save errno immediately. Only EUCLEAN is eligible for the corrupt skip after Phase 2 normalization; a separate on-disk corruption probe must not mask EDEADLK/EINVAL/EIO/EBUSY/ENOMEM. Retire using `bm_cache_invalidate_checked` before counting/logging a skip. If retirement fails, save exact errno and take the existing abort path. The disk probe may remain diagnostic but cannot decide precedence over an actual acquisition error.
- Prepare-EUCLEAN branch: close the current handle with checked cleanup, clear `en->bm` and remove it from `fix->n` exactly once, **then** checked-invalidate that path. A close/retirement error aborts instead of counting a skip. Do not invalidate while holding the same entry's writer lock. Earlier retained paths precede this path in canonical full-path order, so current-path checked invalidation preserves that order. Preserve original prepare error for non-corruption failures and cleanup ownership on every branch.
- Log/count `KF_BMFIX_SKIP` only after successful retirement; include exact path and reason. Preserve keep_marker, preexisting-marker protection, fsync ordering, abort/backoff behavior and startup recovery. Retirement failure may prevent growth, and B then fails the affected ungrown upsert stage closed. No mutation oracle advances on that rejection. Do not promise vacuum always succeeds on retirement failure; assert its existing refused outcome and unchanged keyfile state.

Use the existing test-only invalidation fault if it can be armed and consumed precisely within the isolated daemon operation; otherwise use the Phase 1 request-scoped descriptor. Test exact consumed failure, no successful skip log for that attempt, unchanged keyfile capacity/live/deleted oracle and eventual success after clearing the fault. This compatibility scenario must respect B, not assume writes succeed during failed growth.
