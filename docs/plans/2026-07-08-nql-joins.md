# Add joins to NQL — refactored to direct C structs

## Execution rules

- Branch off `main`: `git checkout -b feat/nql-joins-refactor`
- Build: `SKIP_TESTS=1 ./build.sh`
- Test: `./build/bin/shard-db-test run-all` — must pass after every task
- Leave uncommitted; stop for review after each task

## Problem

The current NQL join implementation passes joins through a JSON intermediate:
the NQL parser builds a JSON string in `join_buf`, `cmd_find_tree` receives
that string and calls `parse_joins_json()` internally to get `JoinSpec` structs.

Every other NQL command produces C structs directly — `nql_parse_filter()`
returns `CriteriaNode *`, `parse_nql_aggs()` returns `NqlAggSpec[]`. Joins
should follow the same pattern: the NQL parser builds `JoinSpec` structs
directly, `cmd_find_tree` receives them as C structs, and `dispatch_nql_query`
owns the lifecycle (free via `free_joins`).

## Syntax (unchanged)

```
--join object local=remote [as alias] [fields f1,f2] [left]
```

Multiple `--join` flags for multiple joins.

## Task 2 — Build `JoinSpec` structs directly in `nql_parse_command()` (`nql.c`)

Replace the `join_buf` JSON-building code in the `--join` flag handler with
direct `JoinSpec` struct population.

The parser reads tokens until it hits the next `--` flag, EOF, or another
positional arg. Token interpretation:

1. First token after `--join` → `object`
2. Token containing `=` → `local=remote`, split on `=`
3. `as` keyword → next token → `as_name`
4. `fields` keyword → next token → comma-split into `proj_fields[]`, `proj_count`
5. `left` keyword → `type = JOIN_LEFT`

On each `--join`, `realloc` the `out->joins` array to grow by one, `memset`
the new slot, fill the fields.

In `nql_free_command()`: replace any `join_buf` cleanup with
`free_joins(cmd->joins, cmd->njoins)`.

Build + run-all. Must be green.

**`query.c`** (line ~8240) — update implementation:

```c
int cmd_find_tree(const char *db_root, const char *object, CriteriaNode *tree,
                  int offset, int limit, const char *proj_str,
                  const char *format, const char *delimiter,
                  const char *order_by, const char *order_dir, int want_total,
                  const char *cursor_json,
                  JoinSpec *joins, int njoins) {
    int r = cmd_find_do(db_root, object, tree,
                       joins, njoins,
                       offset, limit, proj_str,
                       NULL,              /* no excluded_csv */
                       format, delimiter,
                       order_by, order_dir,
                       cursor_json,
                       want_total);
    return r;
}
```

No `parse_joins_json` call — joins arrive as C structs. No `free_joins`
here — caller owns the lifecycle.

Build + run-all. Must be green.

## Design note

This matches the established pattern: every NQL component produces C
structs at parse time. `nql_parse_filter()` → `CriteriaNode *`,
`parse_nql_aggs()` → `NqlAggSpec[]`, and now the `--join` handler →
`JoinSpec[]`. The JSON intermediate is eliminated entirely from the
NQL path.
