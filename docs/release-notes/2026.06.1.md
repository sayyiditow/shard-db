# shard-db 2026.06.1

Query planner overhaul, O_DIRECT I/O series, IO thread pool separation, and cursor+total pagination. No `./migrate` required. Wire-compatible with 2026.05.8. Drop in the new binary and restart.

Headline wins:

- **O_DIRECT full-scan series** — cold full scans (find, count, aggregate, reindex, startup recovery) bypass the page cache via `O_DIRECT`. Adaptive mincore probe: if ≥80% of a file's pages are already resident, opens buffered instead (RAM bandwidth ~30–50 GB/s vs NVMe ~3–4 GB/s).
- **IO thread pool** (`IO_THREADS`, default `4×nproc`) separates I/O-bound work from the CPU pool. Prevents thread starvation on slow-disk workloads; IGB btree Pass 1 and secondary-field map builds now fan out across the IO pool.
- **Bitmap IGB+hbm** — `GROUP BY <bitmap_field>, avg/sum/min/max(...)` materializes only selected aggregates, skipping irrelevant fields via itemized-group-by + histogram metadata.
- **`want_total`** — add `"want_total":true` to any cursor find to get both the page and the full match count in one round-trip. Replaces the two-query count+find pattern.
- **Complete query planner rewrite** — decision-table executors (D1/D2/D3) for composite-index routing, broad-filter ordered-find early termination, range-folding for cursor pagination, materialization + selectivity guards.
- **TOCTOU fix** in `file_is_resident` — `stat()+open()` race replaced with `open()+fstat()`.

## Performance

### O_DIRECT full-scan series

All sequential-read paths that don't benefit from page cache retention now use `O_DIRECT` (Linux) / `F_NOCACHE` (macOS):

- `find`, `count`, `aggregate` scan workers (`od_pread` 32 MB chunks, configurable via `DB_ODIRECT_BUF_MB`)
- `reindex` btree build worker streams
- `recover_streams` at startup (crash recovery shard sweep)
- Compact donor scan
- KF shard walks during bulk operations

**Adaptive residency probe**: `od_open` calls `file_is_resident(path, 80)` before opening. Uses `mmap(PROT_NONE | MAP_NORESERVE)` + 8 evenly-spaced `mincore(2)` probes (~5–15 µs per file, O(1) regardless of file size). If ≥80% of sampled pages are resident → opens buffered (page-cache hit, RAM speed). If cold → opens `O_DIRECT`. Result: warm queries hit RAM speed; cold queries bypass page cache without polluting it for unrelated workloads.

### IO thread pool separation

`parallel_for_io` dispatches to a dedicated IO pool (default `4×nproc` threads, tunable via `IO_THREADS`). Separated from the CPU pool (`THREADS`, default `nproc`) so I/O-bound walks don't starve CPU-bound merge phases.

Migrated to IO pool:
- **IGB Pass 1** (`igb_pass1_worker`) — per-shard btree walk for indexed `GROUP BY`. Each shard walk is I/O-bound (random page-fault reads per btree node); overlapping many concurrent walks cuts cold-btree latency significantly.
- **Secondary group-by field map build** — parallel per-shard btree walk + serial merge replaces the prior sequential loop.
- **Batch-fetch consolidation** — two-phase bulk fetch for wfc_worker MIN/MAX paths and cursor C1 pagination.

### k-way min-heap cursor merge

Cursor pagination with `order_by` on an indexed field (`fetch+sort DESC`) now uses a k-way min-heap across per-shard `BtRangeIter`s instead of a linear scan. Stable `O(log k)` per step; bounded by page depth rather than total record count.

### Bitmap parallel popcount

`GROUP BY <bitmap_field>` with aggregates (avg/sum/min/max) uses parallel bitmap popcount. Slot-level bitmap intersect for criteria evaluation avoids per-record decode on filtered-out slots.

## Features

### `want_total` — cursor + count in one request

Any `find` with `"cursor":{}` or `"cursor":null` can include `"want_total":true`. Response envelope:

```json
{ "rows": [...], "cursor": {"score": 707, "key": "33934139"}, "total": 18432 }
```

`total` is the full match count for the criteria (not just the current page). Computed via the same planner path as `count` — no extra round-trip, no double work.

### Composite index improvements

- Typed binary encoding for composite index keys — correct memcmp ordering across all field-type combinations.
- `reindex --composites-only` flag to rebuild only composite indexes without a full-shard rescan.
- `eq+ORDER BY` composite routing: planner selects D1 (composite range scan), D2 (fetch+sort small candidate set), or D3 (walk order index) based on estimated selectivity.

### Bitmap IGB+hbm

`GROUP BY <bitmap_field>, avg(score)` (and sum/min/max) uses IGB + histogram metadata to materialize only the aggregation target field, skipping irrelevant typed-field decodes. Especially effective on wide schemas with many non-aggregated fields.

## Query planner (complete rewrite)

### Decision-table executors D1/D2/D3

Composite-index `order_by` queries route to one of three executors at plan time:

- **D1** — composite range scan when the criteria prefix matches the index prefix exactly (eq+eq or eq+range). Streams results in order directly from the btree; no sort, no materialization.
- **D2** — fetch+sort for small candidate sets (`K ≤ threshold`). Fetches matching records from the primary index, decodes the order field, sorts in memory. Avoids walking a potentially large order-by index.
- **D3** — walk order index for broad sets. Streams the order-by btree and post-filters against criteria. Cost-effective when the criteria cardinality dominates and the order-by btree is narrow.

### Broad-filter ordered finds

`find` with `order_by` on a non-indexed field no longer buffers all matching records before sorting. The planner walks the order-by index, evaluates criteria per record, and emits results in order — materializing only what's needed per page.

### Range-folding for pagination

`offset + limit` translates to btree range bounds when the `order_by` field is indexed and the cursor is active. Skips the initial `offset` records at the btree level rather than fetching and discarding them.

### Materialization + selectivity guards

- **Materialization guards**: cancel eager record fetch when the KeySet cardinality exceeds `page_depth × RANDOM_SEQ_COST_RATIO` (configurable). Falls back to a lightweight full-scan that avoids the random-I/O penalty.
- **Selectivity guards**: skip multi-index intersection when a single dominant leaf covers >90% of records, picking the cheaper single-leaf path.

## Bug fixes

### TOCTOU race in `file_is_resident` (CodeQL CWE-367)

`file_is_resident` used `stat(path)` to get file size, then `open(path)` to map it. A concurrent `rename` or `unlink` between the two calls could cause the `mmap` to map the wrong file or a zero-length mapping.

Fix: `open(path, O_RDONLY)` first, then `fstat(fd)` on the open fd. Size and mmap now refer to the same inode atomically.

### Writer-preferring rwlock

The prior reader-writer-fairness model allowed readers to starve writers indefinitely on high-read workloads. Index builds and schema mutations (`add-index`, `vacuum`, `rebuild`) could wait unboundedly for an idle-read quiescent window.

New model: once a writer arrives, new readers block. In-flight readers drain, then the writer proceeds. Writers are never starved by a sustained read stream.

### `batch_buf_collect_hash` condvar replaces `sched_yield()` spin

`batch_buf_collect_hash` previously polled with `sched_yield()` while waiting for hash computation results. Replaced with a condition variable (`pthread_cond_wait`) + bounded wake-up. Eliminates CPU burn and scheduling jitter on busy multi-core systems.

### Cross-tenant index cache key scoping

Index cache keys were not scoped by tenant+object — two objects with the same field name in different tenant directories could share a cache entry, returning stale or wrong index metadata.

Fix: cache keys now include the full `dir/object/field` path.

### Binary-key btree correctness

Composite-index pagination callbacks received incorrectly encoded binary keys (missing BE prefix encoding for numeric types). Fix: `typed_field_to_index_key` is now applied consistently on all composite-key btree callbacks.

### Help-drain deadlock prevention

`parallel_for` help-drain path deadlocked when nested work arrived while the help-drain finalizer was running. The finalizer now checks `t_in_io_task` and defers nested dispatch to avoid the lock cycle.

### `bulk_delete` null memcpy guard

`bulk_delete` called `memcpy` from a NULL source pointer when a record had no indexed fields (empty `index.conf`). Now guarded: the memcpy is skipped when there are no fields to index.

## New configuration variables

All optional; existing configurations continue to work unchanged.

| Variable | Default | Purpose |
|---|---|---|
| `IO_THREADS` | `4×nproc` | Dedicated I/O thread pool size. Separate from the CPU-bound `THREADS` pool. |
| `DB_ODIRECT_BUF_MB` | 32 | O_DIRECT buffer size per worker in MB. Peak I/O RAM ≈ `2 × DB_ODIRECT_BUF_MB × IO_THREADS`. |
| `WARMUP` | `async` | Startup cache warmup mode: `async` (detached background thread), `sync` (block until complete), `off` (skip). |
| `AUTO_VACUUM` | 0 | Enable background auto-vacuum thread (`0` = off, `1` = on). |
| `AUTO_VACUUM_INTERVAL_SEC` | 3600 | Auto-vacuum poll interval in seconds. Floor: 60. |
| `VACUUM_RECOMMEND_TOMBSTONE_PCT` | 10 | Tombstone ratio threshold (%) above which vacuum is recommended in `vacuum-check` output. |
| `VACUUM_RECOMMEND_MIN_DELETED` | 1000 | Minimum deleted record count before vacuum is recommended (prevents false positives on small objects). |
| `RANDOM_SEQ_COST_RATIO` | 8 | Planner cost ratio for random vs sequential I/O. Higher values prefer full-scan over random-access plans. |
