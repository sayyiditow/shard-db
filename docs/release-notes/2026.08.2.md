# shard-db 2026.08.2

This release establishes a breaking storage boundary. New objects write
VARIABLE-length segments directly, beginning with ordinary low-numbered files
such as `000000.dat`.

Populated roots require clean-open evidence from 2026.08.1. Startup performs
strict compatibility gating but no storage conversion or automatic index
rebuild. The migration CLI/JSON surfaces, npm `migrate()`, and standalone
`compact` command are removed. Use lightweight `vacuum`, or transactional
`vacuum` with `compact:true` for a full rebuild; the segment compaction helper
alone is not an atomic full-repack contract.

Upgrade runbook: backup → stop writes → run 2026.08.1 once → wait for its
startup sweep → cleanly stop 2026.08.1 → replace with 2026.08.2 → start and
verify. A failed sweep blocks the upgrade. Low-numbered files are valid for
new VARIABLE objects; `048000+` files are valid legacy 2026.08.1 conversion
output. Neither filename range is a format marker.
