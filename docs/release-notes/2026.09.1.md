# shard-db 2026.09.1

This release hardens indexed-write durability and concurrency while improving
throughput for concurrent bulk workloads. It also removes the last TSan
suppressions and closes a broad set of Coverity and lock-safety findings.

## Upgrade requirements

Upgrade only from a database root stamped `2026.08.2`. Stop writes and ensure
the previous release has completed recovery before replacing the binary. This
release accepts `2026.08.2` compatibility evidence and refuses older database
roots; restore a backup or follow the applicable historical migration process
before upgrading.

Marker V2 is forward-replay-only. V1 commit markers are refused at replay, so
all writes must be durable and the database must be recovery-complete before
upgrading. Do not remove or rename marker or segment files during the upgrade.

## Highlights

- Indexed bulk insert, update, and delete now run per-shard deferred commit
  pipelines. Durability syncs are coalesced across concurrent requests, and
  up to four queued same-kind requests can share a commit chain on a busy
  shard.
- Commit markers use the bounded V2 format, with exact-size validation,
  nonce-bearing identities, and replay that re-derives record bytes from the
  named segment records. This removes the V1 marker size ceiling and reduces
  write amplification.
- Bulk index, bitmap, trigram, segment, keyfile, and marker-directory syncs
  are batched and fail closed on lost touch-set or persistence errors.
- Sequence allocation/reset and file operations now use durable temporary
  writes, renames, and directory synchronization with reported failures.
- Bitmap-primary streaming finds no longer re-enter the keyfile lock while
  holding bitmap and keyfile handles, eliminating a production deadlock.
- Registry lifetime, cache invalidation, segment visibility, lock ordering,
  and window-release paths received additional concurrency hardening.
- New objects no longer implicitly create bitmap indexes for undeclared
  `bool` or `enum` fields. Declare the field index explicitly when needed;
  existing persisted index declarations are unchanged.
- The TSan suppression file has been eliminated. New TSan findings now fail
  the gate, and the associated regression coverage has been expanded.

## Compatibility

The release keeps the 2026.08.2 storage boundary and does not provide startup
migration or automatic index rebuild. Run `./shard-db reindex` explicitly when
an index rebuild is required. The wire protocol remains compatible with
2026.08.2.

## Validation

The release gate includes the normal full test suite plus the repository's
ASan/UBSan and TSan full-suite runs. Release artifacts are built for Linux
x86_64, Linux ARM64, and macOS ARM64, with signed tarballs and SLSA
provenance attached by the release workflow.
